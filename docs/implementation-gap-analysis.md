## 仍然存在的缺口

### 1. 登录会话和前端认证接口不完全匹配

前端 API 模式会调用以下接口，但当前后端 OpenAPI 没有对应路由：

- `POST /api/auth/register/send-code`
- `POST /api/auth/login/send-code`
- `POST /api/auth/login/code`
- `POST /api/auth/refresh`

当前后端注册模型只接收账号名、邮箱和密码；前端发送的邮箱验证码字段没有被注册接口校验。Turnstile token 和 `rememberMe` 也没有接入后端验证逻辑。邮箱验证码是你决定留到后面完成的功能，本盘点不会把它当成本阶段必须实现的工作。

后端当前登录只返回 access token，有效期为 7 天；同一个账号再次登录会替换数据库中该账号原有的 token。后端没有 refresh token 接口，因此前端的刷新令牌调用和后端目前不匹配，“记住我”也没有改变后端 token 有效期。

### 2. 账号权限功能仍需运行验收

当前源码已有 `PATCH /api/admin/users/{user_id}/role`，仅组长或旧版管理员可以调用；接口会校验角色、届次和小组，并同步关联成员资料和操作日志。此功能尚未用运行中的 FastAPI 和测试账号做端到端验收。成员资料中的 `members.role` 是“小组风采”显示的职务，和 `users.role` 的登录权限不是一回事；修改账号权限不会覆盖已有的小组展示职务。

### 3. 列表数据和运行状态还有边界

- 管理员账号列表等接口会一次返回全部数据；部分通知、面经等接口有分页，但并非所有列表都支持服务端分页。
- `/api/health` 当前返回固定的 `status=up`，不代表数据库连接正常。
- `backend/OS_club/migrations` 里有 SQL 迁移文件；本次只盘点源码，没有检查这些迁移是否已在当前数据库执行。
- 后端目前没有找到自动化测试套件，因此路由存在和手动点测通过都不能替代持续回归测试。

### 4. 目前没有 AI 后端

当前后端没有 `/api/ai/ask` 路由。AI 助手已约定后续再做，不列为当前阶段的必做项。
