04 / THE CODE PROTOCOL · 生产代码标准

严格审校，杜绝技术债务

在项目组，任何一次代码提交都不是盲目的。我们践行与一线大厂对齐的敏捷迭代规范。

RULE 01

必须通过双人结对审校 (Dual PR Review)

每个功能分支合并至 main 分支前，必须经过一名大三资深成员和一名大二模块负责人共同审查边界溢出与错误兜底。

RULE 02

单元测试覆盖率与自动化 CI 门禁

核心算法与业务逻辑测试覆盖率不低于 85%。GitHub Actions 自动化流水线保障每次构建零回归风险。

RULE 03

架构决策记录 (ADR) 必须同步更新

选型变更或数据模型迭代必须撰写 ADR 归档，让系统设计逻辑清晰透明，杜绝出现“无人知晓的黑盒代码”。

RULE 04

渐进式交付与真实生产观测

部署均接入 Prometheus 与 Grafana 实时看板，对请求延迟、错误率与资源开销进行全天候透明追踪。
